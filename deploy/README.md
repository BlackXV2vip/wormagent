# Deploy — WormAgent Gateway (the `@AGENTEXOS_BOT` runtime)

This folder captures how the **live** WormAgent agent runs on the server:
a systemd user service plus its `~/.wormagent` runtime.

## What's here

| Path | What it is |
|---|---|
| `systemd/wormagent-gateway.service` | systemd user unit that runs the gateway |
| `config/wormagent.json` | gateway config — **secret fields are `REQUIRED`** |
| `config/exec-approvals.json` | exec-approval socket config — token `REQUIRED` |
| `../agent/` | the live agent workspace (persona, tools, memory) |

## First install — only **3 inputs**

The installer (`make setup` or `bash scripts/install.sh`) asks for these three:

| # | Field | What to put |
|---|---|---|
| 1 | API key | your provider key |
| 2 | Telegram bot token | from [@BotFather](https://t.me/BotFather) |
| 3 | Telegram user id | your numeric id ([@userinfobot](https://t.me/userinfobot)) |

**Everything else is generated automatically:**
- `gateway.auth.token` — random
- `exec-approvals.json` `socket.token` — random
- config wiring (allowFrom, approvers, targets), workspace, service, port

Non-interactive:
```bash
WORMAGENT_API_KEY=… WORMAGENT_BOT_TOKEN=… WORMAGENT_TELEGRAM_ID=… bash scripts/install.sh
```

### Manual alternative
Copy `config/wormagent.json` + `config/exec-approvals.json` and replace every
value marked `REQUIRED: ...` with a real value.

## Requirements

- **Node.js >= 22.16.0** (see `package.json` `engines`)
- Linux with systemd (user services)
- A Telegram bot (BotFather) if you want the Telegram channel

## 1. Install the gateway

```bash
npm i -g wormagent
```

The service runs:

```
/usr/bin/node /usr/lib/node_modules/wormagent/dist/index.js gateway --port 18789
```

## 2. Config

```bash
mkdir -p ~/.wormagent
cp deploy/config/wormagent.json ~/.wormagent/wormagent.json
# edit ~/.wormagent/wormagent.json and replace every REQUIRED: ... value
```

## 3. Install the agent workspace (persona)

```bash
mkdir -p ~/.wormagent/workspace
cp -r agent/* ~/.wormagent/workspace/
```

The agent reads its identity from these files each session:
`AGENTS.md`, `SOUL.md`, `IDENTITY.md`, `USER.md`, `TOOLS.md`, `HEARTBEAT.md`.

## 4. Exec approvals

```bash
cp deploy/config/exec-approvals.json ~/.wormagent/exec-approvals.json
# replace the REQUIRED socket token with a long random string
```

## 5. Run as a systemd user service

```bash
mkdir -p ~/.config/systemd/user
cp deploy/systemd/wormagent-gateway.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now wormagent-gateway
systemctl --user status wormagent-gateway
```

Gateway listens on **port 18789** (`gateway.mode: local`).

## Notes

- Real secrets are **never** committed. The repo ships the config skeleton with
  `REQUIRED` markers; fill them on the host only.
- Runtime state under `~/.wormagent` is generated by the gateway:
  `agents/`, `sessions/`, `memory/`, `telegram/`, `identity/`, `devices/`,
  `logs/`, `cron/`, `delivery-queue/`.
